# 01 / 開啟、存檔與實際按鍵

## 方式一：不用安裝開發工具

先完整解壓 ZIP，再開 PLAY_OFFLINE.html。畫面出現後按「在潮息醒來」。瀏覽器若限制本機儲存，請用 Esc → 匯出存檔；不要把瀏覽器快取當唯一備份。

## 方式二：修改用的本機網站

安裝 Python 3 後，在已解壓的專案資料夾開終端機，執行下列命令。保持終端機開著，瀏覽器開 http://127.0.0.1:8000/。結束伺服器用 Ctrl+C。此命令只供本機開發，不是多人遊戲伺服器。

```
python -m http.server 8000 --bind 127.0.0.1
# macOS / Linux 若 python 不存在，改用 python3
# Windows 若使用 Python Launcher，改用 py -3
```

| 用途 | 本版按鍵 |
| --- | --- |
| 移動／跳躍／衝刺 | 方向鍵／Space／Shift |
| 輕擊／重擊 | Z／X；方向＋Z/X 與空中輸入另外分支 |
| 五招職業技 | C、V、B、N、Q；F 是共用既視感，不是第六招 |
| 元素與換位 | 1 火、2 冰、3 雷、4 風、5 土、6 水、7 光、8 影、9 藤、0 引力；S 重射錨點，D 換位 |
| 互動與法則 | E 互動／記憶；J 世界法則；F 短暫既視感 |
| 介面 | M 地圖、L 流派、H 教學、Esc 選單、O 舊背包、K 改鍵 |
| 本版工具 | F2 因果工坊、F8 判定框、F9 內容編輯；也可從 Esc 選單點入 |

概念美術上標的「1～5 技能、Q/E 切元素」不是這份原始碼的鍵位。此版保留原程式鍵位，避免技能與十元素重複綁定。改鍵介面主要覆蓋移動與戰鬥；新工具／選單快捷鍵仍有程式固定綁定。

## 載入與存檔關係

```
index.html
  → 既有引擎與 21.6 模組
  → atlas217_config → hero217_manifest
  → atlas217_core → render → map → editor → ui

進度：game.progress.atlas217
執行狀態：game.aState217()
```

不要調換 index.html 的 script 順序。短期以 21.7 外掛層修改；中期應把堆疊版本整理成單一模組責任，才能降低每次改動被舊鉤子覆蓋的風險。

# 04 / 修改角色：素材、腳底原點與動作

## 現況與真正需要的美術

提供的是帶排版、文字與特效的概念圖，不是完整透明動畫源檔。本版使用既有整身切圖，清理分隔線與鄰格碎片，保留 59 個不重複影格；light 用 2 格，heavy 用另一組 4 格。這讓輕重不同，但不等於重新手繪了高解析連續動畫。

正式製作應請美術輸出同尺寸透明 PNG、固定腳底原點、同一比例與光源的逐格素材。人物與技能光效最好分開。不能把概念圖上的每一個小人直接當成毫無瑕疵的遊戲角色。

| 欄位 | 預設／修改方式 |
| --- | --- |
| hero.atlas | assets/atlas217/hero.webp；新圖可用 assets/atlas217/hero.png。 |
| hero.cell | [160,144] 是目的顯示格大小；修改後會影響外觀縮放，不改物理碰撞。 |
| hero.anchor | [80,130]；畫布上腳底所在位置。角色飄起或陷地時先檢查這個值。 |
| hero.scale | 預設 1。外觀放大不會自動放大 player.w / player.h。 |
| hero217_manifest clips | 每格 [來源X,來源Y,寬,高]；改圖集佈局必須更新。 |
| 角色碰撞 | 既有 player 約 40×60；需要另改初始化、重生與站位檢查，並測牆角／落地／換位。 |

## 修改順序

先用同規格 PNG 替換素材，維持碰撞不變；F9 角色頁更換路徑與原點，套用後看待機、轉向、走、跑、跳、落地、Z、X、受擊。確認腳底穩定後，才調顯示大小。最後才考慮改碰撞，避免同時改三件事找不到原因。

clip 播放規則位於 atlas217_render.js 的 frame216()。目前 walk/run 的步距索引固定按 8 格，jump 使用前 6 格，hurt 使用前 4 格，recover 使用前 6 格。換成更長序列時，必須同步修改索引規則，並非匯入越多格就自動用完。

# 05 / 實作教學：打包自己的角色 PNG

包內工具 tools/pack_sprites217.py 不生成美術；它只把你已完成的等尺寸透明圖片打成圖集與座標表。需要 Pillow，遊戲本身不需要安裝 Pillow。

```
python -m pip install Pillow
python tools/pack_sprites217.py my_frames \
  --cell 160 144 --anchor 80 130 --columns 8 \
  --out sprite_export217
```

上面反斜線換行適用常見 Unix shell；Windows 可將命令接成同一行。my_frames 建立在專案根目錄，各動作一個子資料夾，檔名用 001.png、002.png…，工具按自然數順序排列。

| 目錄 | 最低張數／用途 |
| --- | --- |
| idle / walk / run | 各 8 張。待機、走路、跑步；避免腿部跳格。 |
| jump / recover | 各 6 張。跳躍含上升／滯空／下降／落地；recover 含倒地到起身。 |
| hurt / dash | hurt 至少 4 張；dash 至少 1 張，建議 4～8 張。 |
| light / heavy | light 至少 2 張；heavy 至少 4 張。重攻擊需有明顯蓄勢、重心前移、命中與回收。 |
| cross / spin / cast 等 | 沒有提供的技能 clip 會回退顯示並印警告；正式版本請補齊獨立素材。 |

產出後：hero.png 放入 assets/atlas217/；hero217_manifest.js 覆蓋 js/ 下同名檔；在 data/atlas217_config.js 設 hero.atlas、cell、anchor。保留原檔備份。工具不會擅自覆蓋專案素材。

## 驗收，不只看一張站姿

以固定地面線檢查 10 次跑停、左右翻面、跳到平台邊緣、空中換位接 X。腳底不能漂移，頭部不能忽大忽小，披風不能從隔壁影格穿進來。打擊瞬間要看出肩、胯、武器指向一致；不把四肢拆開任意旋轉來假裝整體動作。

要更換其他可操作角色時，這一版仍共用同一套主角顯示。真正的多角色需要角色 id → manifest／atlas／碰撞／技能／存檔的映射，不能只多放一張立繪就宣稱完成。

# 06 / 技能與連段：數值改法與行為改法

## 輕重攻擊的四個時點

| 項目 | Z 輕擊 | X 重擊 |
| --- | --- | --- |
| 未計裝備判定 | 168×88，Y 偏移 -19 | 272×164，Y 偏移 -86 |
| 首次命中 | 0.065 秒 | 0.215 秒 |
| 可取消時刻 | 0.155 秒 | 0.395 秒 |
| 總時間／基礎傷害 | 0.24 秒／18 | 0.59 秒／36 |
| 人物 clip | light，2 格 | heavy，4 格 |

pulses 是一招的多次命中時刻，不是每個畫面都扣血。cancel 必須晚於最後一個 pulse，duration 必須比 cancel 大。bufferSeconds=0.20：過早輸入不會無限保留；comboGapSeconds=1.05：超時需重新起段。隔牆或不同世界層的敵人不能只因刀光覆蓋就受傷。

在 F9 攻擊頁修改每招；負 knockX 表示拉回，負 knockY 表示挑空。圓形招式在舊判定規約中以 width 作半徑量級、實際盒寬約為兩倍；必須以 F8 顯示為準，不把所有 width 都當單一矩形寬度。

## 五個技能槽的三個倍率

```
"skills": {
  "blade": [
    {"damageScale":1.2,"rangeScale":1.15,"cooldownScale":1},
    {"damageScale":1,"rangeScale":1,"cooldownScale":1},
    {"damageScale":1,"rangeScale":1,"cooldownScale":1},
    {"damageScale":1,"rangeScale":1,"cooldownScale":1},
    {"damageScale":1,"rangeScale":1,"cooldownScale":1}
  ]
}
```

陣列索引 0～4 對應 C/V/B/N/Q。這是局部範例，其他五職業設定不可刪除。damageScale 作用於該招傷害；rangeScale 作用於已接入的射程、範圍與場域；cooldownScale 作用於施放後的冷卻。召喚定位、特殊位移路徑等行為不一定是倍率控制。

## 新增機制，不只是改文案

到 entropy216_combat.js 搜尋 case 'blade'，slot===0 是 C。常用 helper：pulse216(x,y,r,damage,element,opts)、ray216(a,b,damage,element,opts)、field216(kind,x,y,r,duration,extra)、schedule216(delay,fn,tag)。先複製同類招式，保留傷害回報、世界層與延遲隊列，才改行為。

21.7 把職業／槽位的倍率上下文傳入延遲隊列與場域；直接 nHit 也接入倍率。不要同時手乘 damageScale 又交給 wrapper，否則會平方放大。裝備額外傷害以 a217Unscaled 標記排除重複技能倍率。新增第六招還需鍵位、UI、資料驗證與測試，不能只在陣列末尾加物件。

# 07 / 地圖美術：總覽與遊戲地形要分開

![21.7 實際地圖介面截圖；美術總覽、真實資料與區域入口共用同一面板。](new_map.png)

## 美術總覽怎麼換

世界底圖是 assets/atlas217/world_art.webp，八張區域卡是 region_sky/city/coast/fungi/industry/shadow/ocean/snow.webp。區域名稱、分組與示意圖釘位置在 world.biomes；pin 為 0～1 的比例座標。

概念圖原本含有固定探索率、標記與文字。本版以動態資訊面板與「概念地標」覆蓋易誤解處，並明確標「美術總覽／區域位置為示意」。真正玩家座標在「實測通路」與小地圖顯示。正式美術請交付沒有固定 HUD、路線和目前位置的乾淨底圖，才能完全資料化標記。

## 美術不是碰撞

替換 world_art.webp 只會改地圖總覽，不會改遊戲中的平台與背景。遊戲場景仍由原圖層、地形瓦片、碰撞遮罩、結構和敵人構成。要像參考圖的多層瀑布與廢墟，需要遠／中／近景分層素材、可平鋪地塊及逐房構圖，不應把含敵人和 HUD 的整張截圖直接當可走地形。

實測地圖讀 nInit().mask 與 tInit().routes；route217() 依房間 edges 產生建議路線，會列 gate。它不會自動證明單向路、跳躍能力與世界模式均可通過，更不會將角色直接傳到選取的房間。

# 08 / 實作教學：加平台、加怪與新房間

## 在既有 r01 新增可站立平台

F9 → 地圖，選 r01；platforms 內加下列物件。x 相對房間左側；floorOffset 相對 floorY，負值向上。r01 寬 780，平台右緣應落在規劃範圍內。本版新增三座台階已控制在房間內。

```
{
  "id":"my_test_step",
  "x":300, "floorOffset":-165, "w":160, "h":18,
  "modes":["now","past","future","inner"],
  "label":"我的練習平台"
}
```

套用後同類 author217 平台會先移除再重建，避免每按一次多一層。新增平台都是可由下往上穿的一向平台。world.roomPatches 不會挖通岩牆、不會自動生成新房間連線，也不會重排舊地形。

## 加一隻已存在種類的怪物

```
"spawns":[
  {"type":"charger","x":550,"level":2}
]
```

spawns 是該房間物件的欄位，不是放在 platforms 裡。x 是房間內水平位置；本版生成於 floorY 的地面。生怪函數的 y 是腳底，不是左上角。更改倍率只影響之後生成的個體；已存在怪物不會瞬間改 HP。重複套用會避免同一位置的活怪重複產生。

## 新增一整個房間的正確順序

先備份，在 world.js 或實際注入房間的世界模組定義唯一 id、座標、尺寸、floorY、region；把房間加入 rooms 與 roomById，再加入 edges，配置進出門與 gate。接著更新碰撞挖洞／走廊曲線與生成範圍，重建地形／空間索引快取。最後加入敵人、互動點、存檔識別碼、地圖分類與測試。

新房間必驗：左右兩端可實際進出、上下差距可用當前能力跨越、死亡後能重生、裏層與消逝不會刪掉安全地床、沒有只能瞬移脫困的軟鎖。F9 的「新增覆寫」只選既有房間，不支援以上整套拓樸生成。

# 09 / 怪物與頭目：從倍率到新的 AI

## 不用寫 AI 的修改

```
"enemies": {
  "slime": {"hpScale":1.2,"damageScale":0.9,"speedScale":1},
  "charger": {"hpScale":1,"damageScale":1,"speedScale":1.15}
}
```

F9 怪物頁可修改。type 必須存在於 ES9.ENEMIES；slime、charger、archer、scatterer、spider、reflector、mimic 等有效。不要猜一個 crawler id；沒有定義就不會成為新怪物。輸出 HP 可能另受舊區域／精英倍率影響，因此以實際生成後個體為準。

| 需求 | 應修改位置／驗收 |
| --- | --- |
| 改基本數值 | atlas217_config.enemies；重生新個體確認 HP、攻擊、移動。 |
| 改種名與基本行為 | js/config.js 的 ENEMIES，以及 game.js／後續更新敵人的覆寫；搜既有 type 找到所有入口。 |
| 加新 AI | 以 watch → windup → strike → recover 狀態寫，不只換顏色；需要 update 與 render 配套。 |
| 新頭目階段 | 血量門檻、預警、命中判定、收招破綻各自定義；死亡只能結算一次。 |
| 新外觀 | 找到對應 monster family／render 分支與資產 manifest；傳入來源圖和腳底原點。 |
| 圖鑑 | 遇見才解鎖；保留 seen／kills。新種類需可搜尋，未遇見不洩漏完整弱點。 |

## 一隻合格精英的最小規格

例如「潮晶礦甲獸」：遠距離只警戒；蓄力 0.8 秒以地面線提示；衝撞期間最多命中一次；衝過後停頓 1 秒；雷系破甲提供額外破勢，但不必靠特定元素才有任何傷害。這是新增精英的設計範例，尚未自動替換原有 charger。

將攻擊預警與判定記錄在同一份 attackPlan，不要畫在 A 位置卻打 B 位置。用 dummy 測玩家攻擊，用會反擊的新怪測逃生；兩者測試目的不同。一般怪的變種名稱多，不代表每種都有獨立 AI 與專屬動畫。

# 10 / 裝備、製作與升級分支

## 改配方最安全

F9 完整 JSON → gear 找物品 id → 修改 cost。材料 id 固定使用 echo 殘響、glass 潮晶、dust 時塵。新增永久裝備只需一件，不能重複製作；消耗品可多次製作。F2 會依持有、材料、避難所條件顯示是否可用。

```
{
  "id":"myLongBlade", "name":"試作長刃",
  "slot":"weapon", "icon":"crescent",
  "effect":"lightReach", "value":1.25,
  "description":"輕擊範圍乘 1.25；不增加傷害。",
  "cost":{"echo":8,"glass":3}
}
```

可將此物件加入 gear 陣列，沿用現有效果。不要把 effect 改成未實作的時間停止或無限分身。相同 effect 的裝備目前取第一個匹配，不是自動相乘疊加。修改 value 時，description 不會自動更新，要一起改。

| 支援的 effect | 作用 |
| --- | --- |
| lightReach / heavyBreak | 輕擊範圍／重擊破勢；heavyBreak 的 value 控制破勢，傷害 ×1.12 和時間代價仍在 core 固定。 |
| orbitHit / delayedHeavy | 每三次有效攻擊的副射線／重擊延遲追傷。 |
| swapShield / lifesteal | 成功換位盾／實傷吸血；有上限與內置冷卻，訓練不可刷補血。 |
| satellite / groundRefill | 職業技副砲／落地回充時間倍率。 |
| heal / stability | 消耗品回血／降低時空失控；共用 8 秒冷卻。 |

## 分支不是只有文案

branches 存二選一的名稱與說明；真正效果在 branch217()、classAttack()、cast216()、field216() 和 swapElement() 等鉤子。新增第三個分支時，必須新增行為、UI、存檔白名單與測試，不能只在 JSON 加選項。現有分支在避難所可免費改，不能藉此重置冷卻或補滿換位。

# 11 / 換位、世界法則與存檔

## 容量和回充是兩個不同數字

元素 Lv.1／2／3 對應最多 1／2／3 次。消耗共用，不是十種元素各有三次。空中可以執行合法換位，但不在空中回充；落地穩定 0.20 秒後，每 1.25 秒回復一次。泊岸錨環將 1.25 乘 0.75，仍不能突破容量或空中限制。

swap215.js 負責安全落點與原有交換流程；atlas217_core.js 的 tickSwap215() 是本版最後生效的回充規則。改換位時必須測目標失效、牆內、跨層、空中耗盡、連按 D、換元素後的共用餘額；失敗不得只扣次數或只移動其中一邊。

## 法則不應只是色調

now/past/future/heavy/invert/elastic/inner/fungal/decay 是有效模式。碰撞、敵人層、重力、平台存續分別接入既有系統。F 既視感是短暫記錄／重播戰鬥，不是任意選一個世界模式常駐，也不應倒回血量、物品或敵人死亡。

## 存遊戲進度，不是存素材

| 資料 | 備份方式 |
| --- | --- |
| 角色進度 | Esc → 匯出存檔 JSON。21.7 仍兼容既有 ES216_SAVE 包裝，新增 progress.atlas217。 |
| 內容設定 | F9 匯出 atlas217_config.js；這不是玩家存檔。 |
| 角色圖集／地圖／程式 | 複製整份專案或以 Git 版本管理。 |
| 暫態狀態 | 攻擊中的計數、內置冷卻、開發判定開關等不是持久存檔主體；重開後會重建。 |

不要直接刪除 localStorage 解決所有問題：先匯出存檔，確認是版本不相容、瀏覽器拒絕儲存，還是原始碼沒更新。本次自動測試驗證存檔快照含 21.7 數據；about:blank 沙箱環境不代表各瀏覽器跨重開持久化都已驗證。正式發布前需在自己的網址測「存 → 關頁 → 重開 → 匯出 → 匯入」。

## 增加一個訓練關的實作規格

以「水 → 雷 → 空中換位 → 落地」為例：記錄濕潤狀態確實成立、雷傷害確實傳導、D 換位成功、落地回充開始；按鍵有按到但敵人沒受影響不能算完成。用固定訓練對象與重置鍵，成功後顯示是哪一個環節通過。這套逐步評分是後續擴充，現版只有四段說明與命中計數。

## 常見問題與解法

| 症狀 | 先檢查 |
| --- | --- |
| 改了沒有變 | 是否只套用記憶體？是否覆蓋 data/ 正確檔案？是否還在開舊單檔？ |
| 角色黑底或漂浮 | 透明通道、anchor、cell、manifest 是否對上；不要用含背景概念圖代替透明圖集。 |

| 地圖畫了但不能走 | 你改的是美術總覽，還是實體 structures/mask/edges？ |
| 怪沒變強 | 倍率只套新生成個體；檢查 type 拼字與舊區倍率。 |
| 手機按不到／文字小 | 從選單使用觸控入口，檢查面板捲動與 media query；不是將整張桌面畫面縮小就算支援。 |
